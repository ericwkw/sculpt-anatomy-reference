# Sculpt Anatomy Reference

A phone-friendly 3D anatomy viewer for clay sculpting reference. Orbit a model under a
raking studio light, switch layers (skin, muscle, bone, where a model has them), cycle
Skin / Clay / Planes render modes, and save snapshots of angles you want beside you.
Installs to the iPhone Home Screen as a PWA; snapshots stay on the device.

Built with Vite and `<model-viewer>`. **The repo ships no 3D models** — they are large and
licensed separately (see [Adding models](#adding-models)). A shell-only demo, with every
layer shown as "not downloaded", is deployed to
<https://ericwkw.github.io/sculpt-anatomy-reference/> from `master` by
`.github/workflows/deploy-pages.yml`.

## Running it

```bash
npm install
npm run dev -- --host
```

Open the printed Network URL on your phone (same Wi-Fi). In Safari: Share → Add to Home
Screen.

### Always-on server (macOS)

A launchd agent (`~/Library/LaunchAgents/com.sculptref.studio.plist`) can serve the built
site on port 4173 so the phone can reach it without a terminal open. Use the machine's
Bonjour name, `http://<mac-hostname>.local:4173/` — unlike an IP address it survives
network changes, which matters for a Home Screen install. `vite.config.js` allows `.local`
and `.ts.net` hosts; Vite rejects any others.

```sh
npm run build                          # publish changes; the agent serves dist/
tail -f ~/Library/Logs/sculpt-ref.log  # server log
launchctl unload ~/Library/LaunchAgents/com.sculptref.studio.plist   # stop
```

Notes:
- It serves `dist/`, so edits are not live until you rebuild. Use `npm run dev` while working.
- It listens on every interface. Unload it on shared or public networks.
- The plist hardcodes the Node binary and project paths; upgrading Node or moving the
  project breaks it until the plist is updated.

### Phone can't reach the Mac

Some Wi-Fi networks isolate clients: both devices get an address but cannot talk to each
other, so the `.local` name and the LAN IP both time out on the phone. Use
[Tailscale](https://tailscale.com):

1. Install it on the Mac and the phone and sign in to the same account. iOS allows one
   VPN at a time, so turn any other off.
2. On the phone open `http://<tailscale-ip>:4173/` (the `100.x.y.z` address the app shows
   for the Mac). It is stable per device.
3. The `.ts.net` name works only with MagicDNS enabled in the Tailscale admin console;
   otherwise use the IP.

A VPN active on the Mac can compete with Tailscale for the default route. A phone
Personal Hotspot also works as a fallback.

## Adding models

1. Download the models listed in `ATTRIBUTION.md` (Sketchfab, free account) and save each
   as `.glb` in `models-raw/` under the "Save as" name.
2. `npm run optimize`
3. Add an entry with a `credit` block in `src/models.js`.
4. `npm run build` to publish to the always-on server.

Skipping step 3 is fine for a quick look: unclaimed files in `public/models/` appear under
**Unsorted** and are left out of the credits screen.

`.glb` and `.obj` are accepted (an OBJ's `.mtl` and textures are picked up from the same
folder). Sketchfab's glTF download is not read directly; import to Blender and export
glTF Binary, or take the OBJ. A scan split into several meshes is combined first with
`scripts/merge-parts.mjs` (OBJ and FBX; keep parts in a subfolder of `models-raw/`). Each
part's material is named after its source file, and the viewer turns those names into
per-part visibility switches.

### Keeping models fast on phone

Models over roughly 600k triangles can stutter on an iPhone. `npm run optimize` decimates
everything in `models-raw/` to a budget, caps textures at 2048px (re-encoded as JPEG),
quantizes geometry, and writes to `public/models/`. Originals are untouched.

```sh
npm run optimize                       # 600k triangles, 2K textures
npm run optimize -- --budget 150000
npm run optimize -- --max-texture 4096
npm run optimize -- --no-quantize      # if a model looks wrong after optimizing
```

Geometric error is capped at 0.2% of each model's radius. Quantization needs
`KHR_mesh_quantization`, which `model-viewer` supports.

## Rendering

**Lighting.** `public/studio.hdr` is generated by `node scripts/make-studio-hdr.mjs`: one
dominant raking key with weak fill, because model-viewer's default lighting is even and
flattens muscle masses. Edit `LIGHTS` in that script to change it.

**Render modes.** The topbar button cycles Skin → Clay → Planes.
- **Skin** keeps the original texture. It is the default for models with one, and is
  skipped for models without.
- **Clay** detaches the base colour texture (a colour factor alone would only tint it)
  for a matte look that suits the medium. Default for untextured models.
- **Planes** loads a flat-shaded, heavily simplified companion, like blocking in a head
  with a few large cut planes. It appears only for layers that have one.

### Planar studies

```sh
npm run planar                    # 500-triangle budget for every model in public/models/
npm run planar -- --budget 800    # more planes, closer to the source
```

Writes `public/models/planar/<name>.glb` (gitignored). Reduction uses meshoptimizer's
`simplifySloppy` on the whole merged mesh, not edge-collapse: edge-collapse applies its
target per primitive and could not get a 26-part scan below tens of thousands of
triangles. Flat per-face normals are what make the result read as planes. Materials become
uniform matte grey.

Two steps must run in this order before parts are combined, or multi-part scans come out
scrambled: dequantize (each part has its own 16-bit quantization range), then bake every
node's world transform into its mesh. Both are covered by `npm run test:unit`.

## Tests

```sh
npm test           # Playwright, headless
npm run test:ui    # Playwright's interactive runner
npm run test:unit  # Node's built-in runner: planar reduction math
```

Playwright drives a real browser with real mouse and touch input (via CDP) and
hit-testing, so an invisible overlay blocking gestures fails the suite where a synthetic
`element.click()` would pass. It serves a generated stand-in `.glb` for model requests, so
it runs on a fresh clone with no models. Covered: orbit, touch drag, pinch zoom, page not
scrolling on drag, layer switching, snapshot round trip, disabled layers for missing
files, credits on every model, the Skin/Clay/Planes cycle with the part bar, and topbar
and layer bar staying tappable at phone size. The AR-button check is skipped in headless
Chromium.

Not covered: real iOS Safari. Check gestures on the phone.

## Layout

| Path | Purpose |
|---|---|
| `src/models.js` | Model and layer registry |
| `src/main.js` | Viewer wiring, layer and mode switching, snapshots |
| `src/gallery-store.js` | IndexedDB snapshot storage |
| `scripts/optimize-models.mjs` | Decimate raw downloads to a phone budget |
| `scripts/make-planar.mjs` | Generate planar study companions |
| `scripts/merge-parts.mjs` | Combine multi-part OBJ/FBX scans into one `.glb` |
| `scripts/make-studio-hdr.mjs` | Generate the lighting environment |
| `tests/` | Playwright specs and helpers; `make-planar.test.mjs` unit tests |
| `.github/workflows/deploy-pages.yml` | Shell-only GitHub Pages deploy |
| `models-raw/`, `public/models/` | Downloads and optimized models (gitignored) |
| `ATTRIBUTION.md` | Model sources and licence credits |

## Licences

Model licences vary per model, and some are personal-use only, which is why none are
committed or deployed. The credits screen (ⓘ) renders the `credit` field of each layer in
`src/models.js`, and a layer without one fails the test suite. `ATTRIBUTION.md` mirrors
that list; keep both in sync.
